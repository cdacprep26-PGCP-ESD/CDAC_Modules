RISC-V VEGA / THEJAS32 MICROPROCESSOR LAB
ASSIGNMENT QUESTIONS 1-7

Based on the Lyra SDK examples, HAL drivers, and THEJAS32 documentation.
Target board: ARIESv2 / Thejas32
These questions continue the GPIO, UART, timer, and interrupt work in
Questions 1-10.


GENERAL REQUIREMENTS
--------------------
1. Use the Lyra HAL APIs wherever an equivalent driver function exists.
2. Each assignment must include a main.c file and a Makefile.
3. Test the program with make before flashing it to the board.
4. For UART assignments, use huart0 at the default 115200 baud, 8 data bits,
   no parity, and 1 stop bit unless the question specifies otherwise.
5. The RGB LED on ARIESv2 is active-low. Use the RGB_*_SET and RGB_*_RST
   macros from hal/include/aries.h.
6. For timer assignments, use the periodic timer examples as a reference.
   The examples define MILLIS(t) as t * 100000 for the 100 MHz system clock.
7. Keep interrupt callbacks short. Set volatile event flags or counters in a
   callback and perform longer application work in main().
8. Document any external LED, PWM output, button, or other wiring used in the
   assignment. Do not assume that an RGB GPIO pin is a hardware PWM output
   unless the ARIESv2 board documentation confirms that connection.


SECTION C: PWM AND DUTY-CYCLE CONTROL
======================================

QUESTION 1: PWM CHANNEL INITIALIZATION AND LED BRIGHTNESS LEVELS
------------------------------------------------------------------
Connect an external LED, or the instructor-assigned LED output, to a
documented THEJAS32 PWM channel. Configure PWM channel 1 for continuous
operation and display five brightness levels in sequence:

    0% -> 25% -> 50% -> 75% -> 100% -> repeat

Hold each level for one second. At every level, transmit a UART message such
as "PWM duty: 50%". The LED must be fully off at 0% and at full brightness at
100%.

Use a PWM_Handle_t and configure its Channel, Mode, Period, Duty, Alignment,
and State fields before calling the PWM initialization and start functions.
Choose and justify the period value and explain how the duty value maps to
the output waveform.

Required concepts:
- PWM_Handle_t
- PWM_Init()
- PWM_Start()
- PWM_MODE_CONTINUOUS
- PWM_ALIGN_LEFT or PWM_ALIGN_RIGHT
- PWM period and duty-cycle calculation
- UART_Transmit()

Reference files:
- hal/include/pwm.h
- hal/drivers/hal_pwm.c
- hal/include/thejas32.h
- docs/THEJAS32.md
- docs/API-Doc.md


QUESTION 2: TIMER-SCHEDULED PWM BREATHING EFFECT
--------------------------------------------------
Create a breathing LED effect using a hardware PWM channel and a periodic
timer interrupt. The duty cycle must ramp from 0% to 100% and back to 0% in
small, visible steps.

Required behavior:
1. Configure the PWM channel for continuous output.
2. Configure Timer 1 for a short periodic tick, such as 10 ms.
3. TIMER_ElapsedCallback() must only record that a PWM update is due, or
   increment a small update counter. It must not call delayms().
4. The main loop must update the PWM duty value and reverse the ramp direction
   at the 0% and 100% limits.
5. Transmit a short UART message when the ramp changes direction.
6. The effect must continue even while the main loop is processing other
   non-blocking work.

Explain why delayms() must not be used in the timer callback. Also explain how
you safely apply a new duty value when the HAL does not provide a separate
PWM_SetDuty() API.

Required concepts:
- PWM_Init() and PWM_Start()
- TIMER_Init()
- TIMER_Start_IT()
- TIMER_ElapsedCallback()
- volatile flags or counters
- non-blocking main-loop processing

Reference files:
- hal/include/pwm.h
- hal/drivers/hal_pwm.c
- hal/include/timer.h
- hal/drivers/hal_timer.c
- examples/Timer/TimerInterrupt/timer_int.c
- docs/THEJAS32.md

QUESTION 3: UART INTERRUPT PWM SETPOINT CONSOLE
-------------------------------------------------
Build a one-byte UART interrupt console that controls the duty cycle of a
PWM-driven LED. After initialization, accept these commands from UART0:

- 0 through 9: set duty cycle to 0%, 10%, ..., 90% respectively
- f: set duty cycle to 100% (full brightness)
- +: increase the duty cycle by 5%, saturating at 100%
- -: decrease the duty cycle by 5%, saturating at 0%
- s: report the current duty cycle
- o: turn the output off without losing the saved duty setting

Uppercase alphabetic commands must work like their lowercase equivalents.
Ignore CR and LF characters generated by a terminal. The UART receive
callback must only set a completion flag. The main loop must decode the
command, update the PWM register or handle, and transmit the response.

Required concepts:
- UART_Receive_IT()
- UART_RxCpltCallback()
- one-byte interrupt reception
- callback-to-main event communication
- PWM_Handle_t and duty-cycle limits
- command parsing and CR/LF filtering

Reference files:

QUESTION 4: COOPERATIVE MULTI-RATE RGB STATUS SCHEDULER
----------------------------------------------------------
Implement a cooperative, event-driven RGB status application using all three
periodic timers and UART0.

Configure the timers as follows:

- Timer 0: 10 ms scheduler tick
- Timer 1: 500 ms heartbeat event
- Timer 2: 1 second statistics event

Required behavior:
1. Timer callbacks set event bits or increment counters; they must not contain
   delayms(), long loops, or formatted UART output.
2. The 500 ms event must toggle the red LED when heartbeat mode is enabled.
3. The 1 second event must increment a seconds counter and briefly report the
   counter over UART.
4. The scheduler tick must support a non-blocking button debounce window for
   GPIOA pin 3.
5. UART commands must select red, green, blue, all-off, heartbeat, or status
   mode. Use a one-byte interrupt receive operation.
6. All LED changes and UART transmissions must be performed in main().

Include an event-bit table showing which callback sets each bit and which
main-loop action consumes it. Explain how the design avoids the blocking
polling and delay behavior of the earlier assignments.

Required concepts:
- htimer0, htimer1, and htimer2
- TIMER_Start_IT()
- TIMER_ElapsedCallback()
- GPIO external interrupt and software debounce
- UART interrupt reception
- cooperative event scheduling
- volatile shared state

Reference files:
- hal/include/timer.h
- hal/drivers/hal_timer.c
- examples/Timer/TimerInterrupt/timer_int.c
- examples/GPIO/GPIO_Interrupt/gpio_int.c
- examples/UART/UART_Interrupt/uart_int.c
- hal/include/aries.h
- hal/drivers/hal_gpio.c

QUESTION 5: MULTI-BUTTON PLIC EVENT LOGGER
---------------------------------------------
Use two active-high external push buttons connected to GPIOA pins 0 and 1.
Enable both GPIO interrupts and build an event logger that controls the RGB
LED.

Required behavior:
- A pin 0 event toggles the red LED.
- A pin 1 event toggles the green LED.
- If both events occur within a 100 ms window, turn on the blue LED and print
  "COMBINED EVENT".
- Every event must be reported over UART with the pin number and a software
  timestamp measured in timer ticks.
- GPIO_EXTICallback() must only set an event bit and capture the minimum
  information required by main().
- Debounce must be implemented without a long delay or UART transmission in
  the interrupt callback.

Use GPIO_IT_Enable(0) and GPIO_IT_Enable(1), and explain why the corresponding
PLIC sources are GPIO0_IRQn and GPIO1_IRQn. Include a short event timeline in
the report for separate and combined button presses.

Required concepts:
- GPIO_IT_Enable()
- GPIO_EXTICallback()
- GPIO0_IRQn and GPIO1_IRQn
- PLIC interrupt-source mapping
- volatile event masks and timestamps
- timer-based debounce
- active-low RGB LED control

QUESTION 6: UART AND TIMER STOPWATCH WITH GPIO BUTTON CONTROL
---------------------------------------------------------------
Build a stopwatch application for the ARIESv2 board using GPIOA pin 3,
Timer 0, and UART0.

Required behavior:
1. Start in the STOPPED state with the elapsed-seconds counter equal to zero.
2. Configure Timer 0 for a one-second periodic interrupt. The timer callback
   must set a tick flag; the main loop increments the counter only when the
   stopwatch is running.
3. Configure GPIOA pin 3 as an active-high external-interrupt input. Each
   valid button press must toggle between RUNNING and STOPPED.
4. Use the RGB LED to show the state: green while running and red while
   stopped. Turn the other RGB outputs off whenever the state changes.
5. Accept these one-byte UART commands:
   - s: start or stop the stopwatch
   - r: reset the elapsed time to zero
   - p: print the current state and elapsed time
6. Ignore CR and LF characters sent by a terminal.
7. Do not call delayms(), UART_Transmit(), or formatted-print functions from
   an interrupt callback. Use volatile flags and perform application work in
   main().

Print status in a clear format, for example:

    STOPWATCH: RUNNING, elapsed = 12 s
    STOPWATCH: STOPPED, elapsed = 12 s

Required concepts:
- GPIO_Init() and GPIO_IT_Enable(3)
- GPIO_EXTICallback()
- TIMER_Init() and TIMER_Start_IT()
- TIMER_ElapsedCallback()
- UART_Receive_IT() and UART_RxCpltCallback()
- volatile event flags
- active-low RGB LED control

Reference files:
- examples/GPIO/GPIO_Interrupt/gpio_int.c
- examples/UART/UART_Interrupt/uart_int.c
- examples/Timer/TimerInterrupt/timer_int.c
- hal/include/gpio.h

SECTION F: PRACTICAL RGB INTEGRATION

QUESTION 7: UART AND BUTTON CONTROLLED RGB PATTERN PLAYER
----------------------------------------------------------
Create an RGB pattern player that runs on the ARIESv2 RGB LED. The player
must use Timer 0 for scheduling, UART0 for commands, and GPIOA pin 3 for a
physical mode-control button.

The automatic pattern is:

    RED -> GREEN -> BLUE -> repeat

Each color must remain active for 500 ms, and all other colors must be turned
off before the next color is selected.

Required behavior:
1. Configure Timer 0 with a 250 ms periodic interrupt. Count two timer events
   in main() to produce each 500 ms pattern step.
2. The timer callback must only set a flag or increment an event counter.
3. Configure GPIOA pin 3 as an active-high external interrupt input. A button
   press must pause or resume the automatic pattern.
4. Accept these UART commands using one-byte interrupt reception:
   - a: start automatic mode
   - p: pause or resume the pattern
   - n: select the next color immediately
   - o: turn all LEDs off
   - s: print the current mode and color
5. Uppercase commands must work like lowercase commands. Ignore CR and LF.
6. The main loop must apply LED changes and transmit UART responses. Do not
   perform a long delay or UART transmission in a callback.
7. Demonstrate at least ten automatic color changes and show UART output for
   start, pause, resume, next-color, and off operations.

Required concepts:
- RGB_RED_SET/RST, RGB_GREEN_SET/RST, and RGB_BLUE_SET/RST
- GPIO external interrupt input
- TIMER_Start_IT() and TIMER_ElapsedCallback()
- UART_Receive_IT() and UART_RxCpltCallback()
- event flags, counters, and mode handling in main()
- active-low LED behavior

Reference files:

COMMON SUBMISSION INSTRUCTIONS FOR QUESTIONS 1-7
===================================================
For each question, submit the following in a separate Q1, Q2, ..., Q7
directory:

- main.c with suitable comments
- Makefile
- a short README regarding the code flow

Before submission:

1. Run make from the assignment directory and keep the successful build log.
2. Confirm that the expected ELF, HEX, or BIN artifact was produced.
3. Flash only after make completes successfully.
4. For interrupt assignments, verify that callbacks remain short and that
   shared state is declared volatile where required.
6. For UART assignments, show the commands sent and the responses received.
7. For timer assignments, state the clock assumption and the calculation used
   for each LoadCount value.
8. Explain any SDK limitation encountered, especially where a header exists
   but a complete driver or board pin mapping is not provided.

Suggested build and flash sequence:

    make
    make flash

Do not include generated build directories unless the instructor requests
them. Submit source files, Makefiles, reports, and the requested evidence.
