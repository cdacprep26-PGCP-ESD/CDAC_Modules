# Q2. Onboard LED brightness indication using PWM (TIM4 CH1)

**Task:** Generate a 1 kHz PWM on TIM4 CH1 whose duty cycle sweeps up and down (2 s each way). Use the four onboard LEDs as a range indicator (0-24 %, 25-49 %, 50-74 %, 75-100 %) and check CNT, ARR and CCR1 in the debugger. Explain what duty cycle means.

## 1. Configuration, calculations and program flow

### Configuration

```text
Item                            Setting                                              Reason
PD12-PD15                       GPIO_Output, push-pull, initial Low                  Four duty-range indicator LEDs
TIM4                            Internal Clock, Channel1 = PWM Generation CH1        TIM4_CH1 stays on default pin PB6
                                                                                     (unconnected)
TIM4 Prescaler / ARR            15 / 999                                             1 MHz counter, 1000 ticks = 1 ms =
                                                                                     1 kHz
TIM4 PWM channel 1              PWM mode 1, Pulse 0, CH polarity High, OC            Duty = CCR1/1000; glitch-free
                                preload Enable                                       updates
TIM3 (step timer)               Internal Clock, PSC 15999, ARR 9, global interrupt   10 ms tick sets a flag to advance the
                                enabled                                              duty
```

### Calculation

```text
 f_PWM = 16 MHz / ((15 + 1) * (999 + 1)) = 16 MHz / 16 000 = 1000 Hz
 duty = CCR1 / (ARR + 1) = CCR1 / 1000           CCR1 = 0..999 -> 0 % .. 99.9 %
 Step timer: 16 000 * 10 / 16 MHz = 10 ms.   Step = 5 counts -> 200 steps per sweep -> 2 s up, 2 s down
 Range thresholds (CCR1): 0-249 -> 0-24 % | 250-499 -> 25-49 % | 500-749 -> 50-74 % | 750-999 -> 75-100 %
```

### Program flow

```text
TIM3 interrupts every 10 ms and only sets step_due. The main loop sees the flag, moves CCR1 up or down by
5, updates the percentage and writes the four LEDs with HAL_GPIO_WritePin. No delay is used in any interrupt.
The PWM output itself is generated by TIM4 hardware without CPU help.
```

## 3. What to observe and test
```text
Answer to task 7 (explain)
The PWM duty cycle is the fraction of each 1 ms period during which the output is high. A load connected to
the pin receives the supply voltage only during that fraction, so its average voltage and average power
are proportional to the duty cycle (50 % duty gives half the average voltage). Because the switching is far
faster than the eye (or a motor's inertia) can follow, the load behaves as if it received the average. In this
assignment no external LED is allowed and the onboard LEDs are not on a TIM4 output pin, so the PWM
signal itself cannot be seen. The four LEDs are therefore only a visual range indicator driven by
software from the calculated duty, while the real PWM registers (CNT, ARR, CCR1) are checked in the
debugger.

Test condition                         Expected result                                       Actual           Pass/Fail
CCR1 = 0                               duty 0 %, all LEDs OFF
CCR1 = 249 / 250                       24 % all OFF / 25 % PD12 ON (boundary)
CCR1 = 499 / 500                       49 % PD12 / 50 % PD12+PD13
CCR1 = 749 / 750                       74 % two LEDs / 75 % all four
CCR1 = 999 (top)                       direction reverses, dir = -1
ARR in debugger                        999 constant; CNT counts 0-999 repeatedly

Onboard note: TIM3, TIM4, GPIO and the debugger only. The PB6 timer pin is left unconnected.
```
